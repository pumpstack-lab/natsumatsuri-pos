# 夏祭り屋台レジツール

法人の夏祭りで使う、iPad用の**完全オフライン**レジアプリ（PWA）。
フード窓口・ドリンク窓口の2台で同時に使い、売上を正確に集計します。

**サーバーはありません。** データは各iPadの中だけに保存されます。だから電波がなくても絶対に止まりません。

---

## ⚠️ 前日までに必ずやること（これを忘れると当日動きません）

**Wi-Fiのある場所（本部など）で、2台とも次の作業をしてください。**

1. iPadのSafariでアプリのURLを開く
2. 画面下の共有ボタン（□に↑）→「**ホーム画面に追加**」
3. ホーム画面にできたアイコンをタップして、**アプリが開くことを確認する**

これをやると、アプリ本体がiPadの中に保存されます。以降は電波がなくても起動できます。

> **なぜ必要か:** サーバーを持たない代わりに、アプリをiPadに丸ごとキャッシュしています。この作業をしていないと、電波のない屋台で「ページを開けません」となり、何もできなくなります。

## 当日朝のチェックリスト

各iPadで以下を確認してください。

- [ ] **ホーム画面のアイコンから**アプリが起動する（Safariのタブからではなく）
- [ ] **トップ画面の下に出ている「ver 日付」が最新か確認する**
  最新でなければ、Wi-Fiのある場所でアプリを開いて数秒待ち、一度閉じて開き直す
- [ ] **タブは1つだけ。** 同じiPadで2つ目のウィンドウを開かない（顧客番号がズレます）

- [ ] モバイルバッテリーを接続する
- [ ] **紙の伝票と電卓を屋台に置く**（iPadが壊れた・落とした時の唯一の手段）

## 知っておくこと（当日ここでつまずきます）

**顧客番号はフードとドリンクで別々に1から始まります。**
2台のCSVを合わせると「顧客1」が2件出てきますが、**故障ではありません**。窓口ごとの通し番号です。会計を区別するのは「会計ID」の列です。

**支払い完了に確認画面は出ません。**
速度を優先した設計です。押した直後に画面下へ「顧客3　¥1,400 を登録しました」と1〜2秒表示されるので、**そこで金額を確認してください**。間違えていたら履歴から直せます。

**同じiPadで2つのウィンドウを開かないでください。**
ホーム画面のアイコンから1つだけ起動してください。2つ開くと顧客番号が重複します（売上金額は壊れませんが、履歴が読みにくくなります）。

**商品は「削除」できません。**
売り切れスイッチでオフにしてください。当日「やっぱり戻したい」時にすぐ復活できるようにするためです。

## 使い方

### 1. 窓口を選ぶ

トップ画面で「フード」か「ドリンク」を選びます。**選んだ窓口は端末に記憶されます。**

⚠️ 途中で窓口を切り替えると売上が混ざります。切り替え時は確認画面が出ますが、原則として1台1窓口で固定してください。

### 2. 注文を登録する

- 注文された商品を**タップ**します
- 同じ商品を2回タップ＝2個
- 間違えたら伝票の「−」で減らせます
- 合計金額が下に大きく出ます

### 3. お釣りを計算する（必要な時だけ）

- **¥1,000 / ¥5,000 / ¥10,000** をタップすると預かり金が加算されます
  - ¥1,000を2回タップ＝¥2,000（ボタンに「×2」と出ます）
- 端数（¥1,500など）は「**その他**」でテンキー入力できます
  - ボタンで押した分と合算されます
- 預かり金とお釣りが下に出ます
- 押しすぎたら「**クリア**」で預かり金だけ消えます（伝票は残ります）

> **お釣りが不要なら、預かり金を押さずに「支払い完了」を押してOKです。**
> 暗算で済む時に手数を増やさないための設計です。

⚠️ 預かり金が足りないと、赤字で「不足」と出て支払い完了が押せません。

### 4. 支払い完了

「支払い完了」を押すと登録され、すぐ次のお客さんの画面になります。

---

## 間違えた時（履歴から直す）

トップ →「**履歴・集計**」→ 直したい会計をタップ

- 数量を「＋」「−」で変える → 「修正を保存」
- 会計まるごと消したい → 「この会計を取消」

**取消した会計は履歴に残り（グレーの取り消し線）、売上からだけ除かれます。**
消さずに残すのは、後で「何があったか」を追えるようにするためです。

修正した会計にはオレンジの「修正済」バッジが付きます。

> **補足:** 預かり金を記録した会計を、後から金額が増える方向に修正した場合、預かり金とお釣りの記録は自動的に消えます（実際に受け取った金額と食い違うため、嘘の数字を残さない設計です）。売上金額は正しく再計算されます。

## 祭りが終わったら（本部で・Wi-Fi環境）

### 手順（Excelテンプレートを使う・推奨）

**`tools/夏祭り売上_合算テンプレート.xlsx` を使えば、貼り付けるだけで集計されます。**
取消の除外も商品別集計も自動なので、Excelに不慣れでも間違えません。

1. **2台それぞれ**で トップ →「CSV書き出し」→「**明細CSVを書き出す**」
2. 書き出したファイルをPCに送る（AirDropが簡単です）
3. テンプレートを開き、「**貼り付け**」シートを開く
4. **2行目の見本データ（グレーの斜体）を行ごと削除する**
5. 1台目のCSVを開き、**ヘッダー行を除いたデータ**をコピーして、A2セルに貼り付ける
6. 2台目のCSVも同様に、1台目の続きの行に貼り付ける
7. 「**集計結果**」シートを開く → **総売上が出ています**
8. 「**商品別集計**」シートを開く → 商品ごとの個数と金額が出ています

### 手作業でやる場合（テンプレートを使わない時）

1. 2つのCSVをExcelで開き、1つの表にまとめる
2. **「状態」列が「取消」の行を除いて**「小計」列を合計する → **総売上**
3. 商品名でピボットテーブルを作る → **商品別の売上**

> 取消行の除外を忘れると売上が多く出ます。テンプレートを使うことを強く推奨します。

### CSVに入っている列

```
会計ID / 顧客番号 / 窓口 / 商品名 / 単価 / 個数 / 小計 /
会計合計 / 預かり / お釣り / 状態 / 登録時刻
```

- 1行＝1商品です（1つの会計で3品買えば3行になります）
- 「小計」＝単価×個数
- 「状態」は「有効」か「取消」

### 検算のしかた（必ずやってください）

**2つの数字が一致すれば、集計は正しいです。**

1. 各iPadの「履歴・集計」画面に出ている**総売上**を2台分メモする
2. その2つを足した金額と、テンプレートの「集計結果」シートの**総売上**を見比べる

一致しなければ、CSVの貼り付け漏れか、行の重複です。テンプレートの「読み込んだ明細行数」を確認してください。

テンプレートには他にも検算用の数字が出ています。

| 項目 | 見かた |
|------|--------|
| 有効な会計の件数 | 2台の「会計数」の合計と一致するはず |
| 取消した会計の件数 | 取り消した回数と合っているか |
| 取消の合計額 | この金額は総売上に**含まれていません** |
| 商品別集計シートの合計 | 集計結果シートの総売上と一致するはず（しなければ商品名の書き漏れ） |

> **サマリーCSV**（1行＝1会計）も書き出せます。そのまま印刷して目視確認したい時に使ってください。

## 困った時

| 症状 | 対処 |
|------|------|
| アプリが開かない（屋台で） | 前日のホーム画面追加を忘れている可能性。紙の伝票に切り替えて、後で入力 |
| 画面が固まった | アプリを閉じて開き直す。**登録済みの売上は消えません** |
| iPadの電源が落ちた | 充電して再起動。**支払い完了まで押した会計は残っています**（入力途中のものだけ消えます） |
| 商品が売り切れた | 「商品の設定」でスイッチをオフ。登録画面から消えます（過去の売上には影響しません） |
| 当日メニューが変わった | 「商品の設定」で追加・編集できます |
| CSVがExcelで文字化けする | 起きない設計です（BOM付きUTF-8）。それでも起きたらメモ帳で開いて確認 |

## 開発者向け

```bash
npm test        # テスト実行（57件）
npm run serve   # ローカルサーバー（http://localhost:8080）
```

### 構成

```
src/core/     計算ロジック（純粋関数・DOMもDBも触らない → Nodeでテスト可能）
  money.js      金額・お釣りの計算
  sale.js       会計の生成・修正・取消
  summary.js    売上集計・商品別集計
  csv.js        CSV生成
  products.js   商品マスタ・仮メニュー
src/db.js     IndexedDB の読み書き
src/ui/       画面5枚 + 状態管理
sw.js         Service Worker（オフラインキャッシュ）
src/version.js  バージョン表示（更新時はここと sw.js の CACHE 名を同時に変える）
tools/        Excel合算テンプレート
```

### 設計上の重要な決まり

- **金額はすべて整数（円）**。浮動小数点は使わない
- **会計の items には商品名と単価をコピー保存**する。マスタの価格を変えても過去の売上は変わらない
- **取消は削除しない**（`status: 'voided'`）。集計から除くだけ
- `src/core/` は DOM・IndexedDB を一切importしない（テスト可能性を守るため）

### バージョンを更新するとき

`src/version.js` の `BUILD` と `sw.js` の `CACHE` 名を**同時に**変更してください。
どちらか片方だけだと、iPad側で古いコードがキャッシュされたまま残ります。

トップ画面下部に表示される「ver 日付」で、端末に入っている版を確認できます。
